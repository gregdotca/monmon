# Changelog

## 2026-10-25

- Make `install.sh` check the Raspberry Pi's SSH host key before running Ansible. Ansible won't log in with a password to a host whose key isn't in `~/.ssh/known_hosts`, so a first install on a new Pi failed unless you'd logged in by hand first, and after reflashing the SD card SSH refused the Pi's new key. SSH itself does the checking, with connection sharing turned off and without logging in, so its own settings decide where known keys are kept, as they do for Ansible. Now, for a Pi it hasn't seen, `install.sh` has SSH save the key, checks it was saved, and shows its fingerprint; if the saved key no longer matches, it stops and shows the `ssh-keygen` command that removes the old one from the file SSH found it in, to be run only if the Pi was reflashed or replaced; and if it can't reach the Pi over SSH, it says so. `README.md` describes the check, and that running the playbook by hand needs the key saved first.
- Fix logins and `sudo` taking minutes on the Raspberry Pi after the install sets a new password. The new password was hashed with Ansible's default of 656,000 SHA-512 rounds instead of the Linux default of 5,000, so every password check (SSH logins and `sudo`) took tens of seconds of CPU on a Pi Zero, and the next deploy failed with "Timeout (12s) waiting for privilege escalation prompt". The hash now uses 5,000 rounds. A Pi that already has a slow hash can be fixed by setting its password again with `passwd` on the Pi.
- Let the install use a username other than `pi` on the Raspberry Pi. Raspberry Pi Imager asks for a username, and Raspberry Pi OS hasn't created a default `pi` user since 2022, so an install on a Pi with any other username failed at its first step. `install.sh` now asks for the username (press Enter for `pi`), checks it uses only lowercase letters, digits, `_`, and `-` (as the usernames Raspberry Pi OS creates do), and passes it to Ansible as `monmon_user`. `ansible/inventory-install` logs in as that user (`pi` if it isn't set), the playbook no longer sets `remote_user: 'pi'`, and the final task sets the new password for that user. The prompts, messages, and `README.md` now say "the user" instead of "the pi user", and the README says to pass `monmon_user` when running the playbook by hand.
- Remove the HDMI display methods, `gui` and `cli`, so the Waveshare LCD and the status page in a web browser are now the only displays. `gui` installed a desktop and opened the status page full-screen in the Midori web browser, but Midori isn't packaged in Debian 12 (bookworm) or 13 (trixie), so a `gui` install failed, and its LXDE desktop setup no longer matches current Raspberry Pi OS. `cli` showed the page as plain text with the Lynx browser, and started from the `pi` user's `~/.bashrc`, so it also took over every SSH login after a 30-second wait. Both only showed the same status page any browser on your network shows, so no monmon features are lost. `install.sh` no longer asks for a display method, the playbook's display tasks and templates (`midori-config.j2` and `pixel-autostart.j2`) are gone, `ansible/group_vars/all.yml` (which only held the display settings) is removed, and `README.md` is updated. A Pi already set up with `gui` or `cli` keeps that setup until its SD card is reflashed.

## 2026-10-24

- Stop the playbook from failing while it waits for the Raspberry Pi to reboot. The reboot at the end of the install waited up to 5 minutes for the Pi to come back, and the first boot after the install's OS upgrade can take longer than that on a Pi Zero, so the playbook failed even though everything was installed, and the new `pi` password was never set. The new password and the reboot are now one final task: it sets the password (if you entered one), and only then schedules a reboot a few seconds later (`systemd-run`), without waiting for the Pi to come back. The task's input is never empty, since Ansible doesn't send empty input, which would leave the task waiting forever when no new password was entered. `install.sh` now says the Pi is rebooting and can take a few minutes to come back, names the new final task in its failure message, and no longer suggests re-running it after "red text", since it now stops with its own message when the playbook fails.
- Make `install.sh` ask for the `pi` user's current password itself, once, instead of having Ansible ask for it with `--ask-pass`. On a fresh install of Raspberry Pi OS based on Debian 13 (trixie), the `pi` user needs a password for `sudo`, so the playbook failed at its first step with "Missing sudo password". The sudo password is the same as the login password, so rather than a second prompt, `install.sh` passes the password to Ansible in the `MONMON_PI_PASSWORD` environment variable, and `ansible/inventory-install` uses it for both SSH and sudo. It isn't saved to a file or shown in the process list, and `install.sh` asks again if it's left blank. `README.md` now says to set `MONMON_PI_PASSWORD` when running the playbook by hand.
- Stop the playbook from using sudo on the local system. The tasks that check whether your custom configuration files exist run on the local system (`delegate_to: localhost`) but inherited the playbook's `become: true`, so they ran `sudo` locally and failed with "sudo: a password is required" wherever sudo needs a password. They now set `become: false`, since checking a local file needs no root access.
- Install the Python libraries monmon needs (`RPi.GPIO`, `spidev`, `xmltodict`, and `requests`) as Debian packages with apt instead of with pip. Current Raspberry Pi OS (bookworm) blocks `pip install` into the system Python (PEP 668, "externally-managed-environment"), so the playbook failed at that step. `python3-pip` is no longer installed, since nothing uses it.
- Remove the Debian Buster backports setup for Monit. The monmon role added three signing keys with the deprecated `apt-key`, one of which can no longer be added, so the playbook failed at its first real task on current Raspberry Pi OS (bookworm). The monit role also added a `buster-backports` apt source that Debian no longer serves from `deb.debian.org`. Monit is in the OS's own repositories, and the backports pin was already unused, so the key task is gone, and both roles now delete `/etc/apt/sources.list.d/buster-backports.list` if an earlier install left it, before updating the repos.
- Make `install.sh` stop with an error when the Ansible playbook fails, instead of always printing "Installation complete!". The message says the tasks after the failure didn't run, so a new `pi` password entered at the prompt hasn't been set, unless the failure was in that final password task itself, in which case either password may now work.
- Make `install.sh` work on control machines that don't use apt. It used to run `sudo apt update` and `sudo apt install` every time, which failed on other systems (such as Arch Linux) while the script carried on to a playbook run that couldn't work. It now checks for `ansible-playbook`, `ansible`, and `sshpass`, and asks Ansible to make a SHA-512 password hash (newer Ansible can do this itself; older versions need passlib), installs only what's missing with apt or pacman (adding passlib only if Ansible can't hash without it), and stops with a list of what to install if anything is still missing. `README.md`'s install note now says so.

- Stop storing the Raspberry Pi's password in `ansible/inventory-install`. It held the old Raspberry Pi OS default for the `pi` user, which was public in this repository, kept every install on that default (changing it broke later deploys), and no longer works on Raspberry Pi OS releases since 2022, which don't ship a default password. `install.sh` now runs `ansible-playbook` with `--ask-pass`, so Ansible asks for the current password and never saves it.
- Add an optional prompt to `ansible/install.yml` for a new `pi` password, typed twice and hidden, and taken literally even if it contains `{{` or `{%`; leave it blank to keep the current one. The new password is stored on the Pi as a SHA-512 hash, is never printed (`no_log`), and is set in a final play after the reboot, so the earlier plays can still connect with the current password. `install.sh` now also installs `python3-passlib`, which Ansible uses to make the hash.
- Update `README.md`'s install steps: create a `pi` user with your own password and SSH turned on (instead of the old default credentials), what the two password prompts mean, and `--ask-pass` for running the playbook by hand.
- Add `ACR.md`, an [AI Code Rating](https://aicoderating.com/) file (B1a) that says how much of monmon's code AI wrote and how it's checked, and an ACR badge under the title in `README.md`.
- Stop `install.sh` from editing tracked files. It used to write the Pi's IP address and the display method into `ansible/inventory-install`, `ansible/roles/monmon/templates/nodes.j2`, and `ansible/group_vars/all.yml` with `sed`, which left the working tree changed after every install and could get those values committed by mistake. It now passes them to `ansible-playbook` as extra variables (`monmon_ip_address` and `installation_type`), and the inventory and the default Node file read them from there. `installation_type` now defaults to `none` in `group_vars/all.yml`.
- Make `install.sh` check that the Pi's IP address is a valid IPv4 address, asking again until it is, and pass the extra variables to Ansible as JSON, so a mistyped address can't set other Ansible variables or break the command.
- Document in `README.md` how to run the Ansible playbook by hand, with the two extra variables it now needs and the custom configuration files it expects in the `ansible` folder.
